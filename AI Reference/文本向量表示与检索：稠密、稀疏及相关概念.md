# 文本向量表示与检索：稠密、稀疏及相关概念

> 稠密向量是绝大多数分量都非零的向量。在 LLM 应用中，它常用于表示文本的语义，让程序能够用数值计算比较文本的相似程度。

## 1. 从直觉理解

向量可以先理解成一个有顺序的数字列表：

```text
[0.12, -0.34, 0.87, 0.06]
```

这个向量有 4 个维度，且每个分量都非零，因此是一个稠密向量。实际文本表示的维度由模型和配置决定，上面只是演示。

假设要比较下面三句话：

- A：「如何重置密码？」
- B：「忘记密码后怎样重新设置？」
- C：「今天北京的天气怎么样？」

合适的文本 embedding 模型通常会让 A、B 的向量更接近，而让它们与 C 的向量相对远一些。这样，即使两句话的用词不同，也有机会通过语义相似度找到彼此。

**这里有两个不同的概念：稠密描述数值的分布；语义来自模型的训练。** 随机生成一组非零数字也是稠密向量，但不因此具有有用的语义。

## 2. 稠密向量与 Embedding 的关系

Embedding（嵌入）是把文本、图片等对象映射为向量表示的过程，也常用来指得到的表示。在语义检索中，文本 embedding 通常采用稠密向量。

```text
文本 → embedding 模型 → 稠密向量 → 相似度计算 → 检索结果
```

这两个词并不完全等价：

- **Embedding** 强调「对象如何被表示」。
- **稠密向量** 强调「向量的大多数分量非零」。
- Embedding 也可以采用稀疏表示；稠密向量也可以表示与文本无关的数据。

在学习得到的文本向量中，一个维度通常不能直接命名为「天气」「情绪」或「密码」。语义由多个维度共同编码，维度中的负值也不表示负面情绪。

## 3. 稀疏向量：含义、表示与计算

稀疏向量（Sparse Vector）的绝大多数分量为零。例如，在一个很大的词表中，一篇短文只涉及少量词，便可以只在对应位置记录非零权重。

### 从词表构造一个例子

假设固定词表如下，每个位置的含义对所有文档都一致：

```text
位置：  0     1     2     3     4     5     6     7
词项：密码  重置  天气  订单  退款  登录  手机  发票
```

对已经分词的文本「密码 重置 密码」，按出现次数编码：

```text
完整表示：[2, 1, 0, 0, 0, 0, 0, 0]
稀疏存储：{0: 2, 1: 1}
```

后者只保存「位置 → 数值」，但向量的维度仍然是 8，并没有变成 2 维。实际存储还需要知道总维度；解释这些位置时，需要共享词表或特征映射。

这个小词表用于演示。在大词表中，一篇短文可能只激活极少数位置，稀疏性会更明显。可以用非零分量数量 `nnz` 描述它：

$$
\text{非零比例}=\frac{\operatorname{nnz}(\mathbf{x})}{d},\qquad
\text{零值比例}=1-\frac{\operatorname{nnz}(\mathbf{x})}{d}
$$

其中 $d$ 是总维度。「稀疏度」有时用于指不同的比例，使用时应说明定义。稠密与稀疏之间没有适用于所有场景的统一百分比界线。

### 为什么适合词项匹配？

假设查询「密码 重置」编码为 `q = {0: 1, 1: 1}`，上面的文档为 `d = {0: 2, 1: 1}`，则点积为：

```text
q · d = 1 × 2 + 1 × 1 = 3
```

只需计算双方共同的非零位置。「天气」对应的位置与这两个词都不重合，使用这种简单编码时，点积为零。注意：这里的原始词频点积只是计算示例，并不是 BM25 的计算公式。

稀疏存储通常随非零项数量增长，但还要存储索引，因此只有足够稀疏时才有明显空间收益。检索时也可以使用倒排索引：从查询词项直接找到包含相应特征的文档。

### 稀疏向量一定没有语义能力吗？

不一定。**稀疏只描述零值多，并不规定权重是如何产生的。**

- 传统词袋与 TF-IDF 主要依赖词项重合；如果没有同义词扩展等处理，「重置密码」与「找回口令」可能无法匹配。
- 学习型稀疏表示可以由模型预测词项权重，并激活原文中没有直接出现的相关词项，从而支持一定程度的语义匹配。
- 稀疏向量的维度也不一定对应自然语言词项；只有词表型表示才具有这种解释方式。

## 4. 稠密、稀疏及相关概念的区别

### 稠密向量与稀疏向量

| 对比项 | 稠密向量 | 稀疏向量 |
| --- | --- | --- |
| 数值分布 | 绝大多数分量非零 | 绝大多数分量为零 |
| 简化示例 | `[0.2, -0.5, 0.8, 0.1]` | `[0, 0, 0.8, 0, 0, 0.3, 0, 0]` |
| 文本中的典型表示 | 模型学习的语义 embedding | 词袋、TF-IDF、学习型稀疏表示 |
| 维度含义 | 通常不能逐维直接解释 | 词表型表示的维度通常对应词或 token |
| 常见检索优势 | 匹配同义表达、语义相近的内容 | 匹配专有名词、编号等明确词项 |
| 常见存储方式 | 存储所有分量 | 仅存储非零分量的位置和数值 |

「稠密」不等于「维度高」，「稀疏」也不等于「维度低」。稀疏向量可以拥有非常多的维度，只是大部分位置为零。

检索效果取决于模型、数据和任务。工程上常采用**混合检索**，结合关键词检索与稠密向量检索，再融合结果或进行重排。

### One-hot、词袋、TF-IDF 与 Embedding

这些概念不在同一层级：**稠密／稀疏是表示的性质；one-hot 和词袋等说明如何编码；embedding 强调对象到向量空间的映射。**

| 概念 | 它是什么 | 非零值表示什么 | 与稠密／稀疏的关系 | 主要区别或限制 |
| --- | --- | --- | --- | --- |
| One-hot（独热编码） | 用一个位置标识一个类别或 token | 唯一的 `1` 表示该类别被选中 | 高维时是典型稀疏向量 | 不同类别的向量彼此正交，本身不表达语义相近程度 |
| Multi-hot（多热编码） | 标识多个类别或词项是否出现 | 每个 `1` 表示对应项出现过 | 只激活少量位置时是稀疏向量 | 能表示多个项，但不区分出现一次还是多次 |
| Bag of Words（词袋，BoW） | 忽略词序，用词项统计表示文本 | 计数型词袋的值是词频；二值词袋只记录是否出现 | 大词表、短文本下通常稀疏 | 强调词项出现情况，无法保留完整语序；二值词袋可用 multi-hot 表示 |
| TF-IDF | 结合文档内词频与语料中的逆文档频率进行加权 | 词项在当前文档与语料背景下的统计权重 | 通常得到稀疏向量 | 相比原始计数，降低普遍词项的影响；仍主要依赖词项重合 |
| 学习型稀疏表示 | 由模型学习少量活跃特征及其权重 | 模型预测的特征权重 | 输出为稀疏向量，也常称 sparse embedding | 可支持语义扩展，但效果取决于训练；不等于原始词频 |
| 稠密语义 Embedding | 由模型把语义信息编码到多个连续维度 | 多维共同表达的潜在特征 | 输出通常为稠密向量 | 能匹配语义相近的表达，但对编号、否定等细节未必敏感 |

使用同一个词表观察差异：

```text
词表：[密码, 重置, 天气, 订单, 退款, 登录, 手机, 发票]

单个词「密码」的 one-hot：          [1, 0, 0, 0, 0, 0, 0, 0]
文本「密码 重置 密码」的 multi-hot：[1, 1, 0, 0, 0, 0, 0, 0]
同一文本的计数型词袋：             [2, 1, 0, 0, 0, 0, 0, 0]
同一文本的 TF-IDF：                [a, b, 0, 0, 0, 0, 0, 0]
```

这里 `a`、`b` 取决于词频定义、语料中的文档频率及归一化方式，不能只凭这一句话确定。稠密 embedding 的维度则不再与这个词表逐项对应，因此不应把它理解为「把词频中的零替换成小数」。

### BM25、向量检索与混合检索

| 概念 | 所属层级 | 与向量表示的关系 |
| --- | --- | --- |
| BM25 | 词项相关性评分方法 | 根据查询词项、词频、逆文档频率与文档长度等计算分数；通常配合倒排索引使用，不是稀疏向量本身的别名 |
| 向量检索 | 检索方法 | 使用点积、余弦相似度或距离寻找相关向量；广义上可处理稠密与稀疏表示，具体取决于系统支持 |
| 混合检索 | 多路检索的组合策略 | 常见做法是结合 BM25 与稠密向量检索，也可结合学习型稀疏检索与稠密检索 |
| Reranker（重排模型） | 候选结果的再排序阶段 | 对已召回的查询与文档重新评估相关性，不等于另一种稠密／稀疏向量类型 |

例如，对「错误码 E1042，登录失败怎么办？」进行检索时，词项检索可以利用 `E1042` 的精确重合，稠密检索可以寻找语义相近的故障描述。融合时，BM25 分数与余弦分数不能默认直接相加，需要采用适当的分数处理或基于排名的融合方式。

## 5. 如何比较两个向量？

常见方法包括余弦相似度、点积和欧氏距离，其中余弦相似度比较的是两个非零向量的方向：

$$
\operatorname{cosine\_similarity}(\mathbf{q},\mathbf{d})
= \frac{\mathbf{q}\cdot\mathbf{d}}{\|\mathbf{q}\|_2\|\mathbf{d}\|_2}
$$

- 数学取值范围为 $[-1,1]$，数值越大表示方向越接近。
- 如果两个向量都已进行单位长度归一化，点积就等于余弦相似度。
- 相似度分数不是「答案正确的概率」；`0.8` 不代表 80% 正确，也不存在适用于所有模型的统一阈值。

例如，查询向量 `[1, 1]` 与候选向量 `[2, 2]` 的余弦相似度是 `1`：它们长度不同，但方向相同。这里使用手工数字演示数学关系，不代表真实模型输出。

**比较向量时必须使用兼容的表示空间。** 实践中通常使用同一个 embedding 模型，或明确配套的查询与文档编码器；仅仅维度相同，不意味着两个模型生成的向量可以直接比较。距离度量也应遵循模型的使用约定。

## 6. 在 LLM 与 Agent 中有什么用？

### RAG：为回答检索参考资料

```text
准备资料：文档 → 分块 → embedding → 存入向量索引
用户提问：问题 → embedding → 检索相近片段 → 将片段原文交给 LLM → 生成回答
```

稠密向量在这里主要负责「找资料」。典型文本 RAG 交给生成模型的是检索到的文本片段，而不是直接让模型阅读向量中的数字。检索到的内容是否正确、是否足以回答问题，仍需要进一步判断。

### Agent 记忆：召回相关历史

将历史对话、任务记录或经验生成 embedding，便于 Agent 在新任务中检索相关内容。这是一种外部记忆方案，不等于修改了 LLM 的模型参数。

### 语义路由：选择候选处理流程

将用户请求与预先定义的意图示例比较，例如「查天气」「检索知识库」「查询订单」，再根据相似度选择候选路线。

向量相似度可以辅助路由，但不等于完成工具调用、权限判断或参数校验。相关笔记：[[LLM Rewrite 资料]]。

### LLM 内部表示：注意区分用途

LLM 内部的 token embedding 和隐藏状态也常表现为稠密向量，但它们不自动等于适合句子检索的 embedding。直接取某层隐藏状态做平均，不保证得到高质量的语义检索表示；效果与训练目标、取层及聚合方式有关。

## 7. 实践中容易误解的地方

- **不是压缩后的原文文件。** 文本 embedding 通常不能无损还原原文，因此检索系统需要保留原文或可回溯的引用。
- **维度越高不一定越好。** 效果还取决于训练数据、任务匹配程度和文档分块等因素；更高维度通常增加存储与计算开销。
- **语义相近不等于事实一致。** 「支持退款」与「不支持退款」讨论同一主题，向量可能接近，但含义存在关键差异。
- **更换模型通常需要重新编码资料。** 不能只更新查询侧模型，就默认它仍能与旧文档向量兼容。

一句话记忆：**稠密向量是数值表示形式；embedding 模型赋予表示可用于任务的结构；检索系统利用这种结构寻找相关内容。**
